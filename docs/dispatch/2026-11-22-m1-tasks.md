### 3.1 core 新增 `packages/core/src/worktree.ts`（研发A）

```ts
export interface WorktreeHandle {
  taskId: string;
  agentId: string;
  path: string;        // 绝对路径：<worktreesDir>/<taskId>
  branch: string;      // cg/<agentId>/<taskId>
  baseCommit: string;  // 创建时主仓库 HEAD 的 commit sha（diff 基线）
}

export class WorktreeManager {
  constructor(opts: { repoRoot: string; worktreesDir?: string });
  // worktreesDir 默认 <repoRoot>/.cg/worktrees
  create(agentId: string, taskId: string): Promise<WorktreeHandle>;
  list(): Promise<WorktreeHandle[]>;
}
```

冻结语义：
- `create` **按 taskId 幂等**：该任务的 worktree 已存在则直接返回现有 handle（崩溃 recover 后重消费复用同一 worktree，不新建）。
- 新建执行 `git worktree add -b cg/<agentId>/<taskId> <path> HEAD`（在 repoRoot 下）；baseCommit 取创建时 repoRoot 的 HEAD。
- **M1 不做自动清理**（PM 仲裁）：成功保留供审查 diff，失败保留供排查；`remove`/清理 API 留待用户决定清理策略后再加。崩溃恢复的一致性由幂等 create 保证。
- 创建失败（git 报错等）→ 该 run 走 failRun，任务 failed，M1 无重试。
- core 不得出现任何具体 agent 名（agentId 只是参数）；worktree 模块不得 import plugins。

### 3.2 WorkerHost 构造 opts 增量（研发A，`packages/core/src/worker-host.ts`）

```ts
constructor(queue: TaskQueue, plugins: AgentPlugin[], opts?: {
  pollIntervalMs?: number;      // M0 已有，默认 200
  worktrees?: WorktreeManager;  // M1 新增，可选
})
```

冻结语义：
- **不传 worktrees 时行为与 M0 完全一致**（workdir = process.cwd()），echo 及全部 M0 测试不得受影响。
- 传 worktrees 时，每次 launch：先 `create(agentId, taskId)` → `ctx.workdir = handle.path`，并 reportEvent("worktree", handle.path)。
- execute 成功且 `spec.artifacts` 含 `"diff"` 时，WorkerHost 在 worktree 内执行 `git add -A` 后 `git diff --cached <baseCommit>`，把结果作为 `{ kind: "diff", content }` **追加**进 RunResult.artifacts 再 completeRun（插件返回的 artifacts 保留）。这是宿主内部行为，不改任何公开签名。
- execute 抛错/abort 照旧 failRun/completeRun(ok:false)，worktree 保留。

### 3.3 RunContext.workdir 语义变更（文档性，类型不变）

- M0：恒为 process.cwd()。
- M1：启用 worktrees 时为**该任务专属 worktree 的绝对路径**。插件必须把它作为子进程 cwd，一切文件改动只发生在这里。插件不得假设 workdir 是主仓库。

### 3.4 禁止 push 的落地（跨 core/plugins/cli，PM 仲裁）

1. CLI 构造 TaskSpec 时 constraints 固定注入：「禁止 git push / 任何远端写操作；禁止触碰主工作区；只在当前工作目录内改动」。
2. codex 适配器用 `-s workspace-write` 沙箱（写限工作目录、默认禁网）——机制级兜底。
3. gemini/claude headless 无同等沙箱，靠约束文本 + 验收时核查远端未变（残留风险已知，记录在案；M2 再评估更强隔离）。
4. 任何适配器/worker 代码自身不得执行 push。

### 3.6 适配器公共行为约定（研发B）

- spawn 必须**可注入**（构造 opts 传 spawner 工厂），单测/契约套件全部走 stub，不拉真实 CLI。
- prompt 由 TaskSpec 结构化字段拼装（goal/context/instructions/constraints/acceptanceCriteria），不得接收用户原文（M1 CLI 直填例外下二者相同，但代码路径必须走 TaskSpec）。
- 子进程 cwd = ctx.workdir；stdout/stderr 关键节点经 ctx.reportEvent 上报（低密度摘要，别整段灌库）。
- abort（ctx.signal）→ SIGTERM 子进程，宽限 5s 后 SIGKILL；返回 `{ ok:false, summary:"aborted" }` 或抛出（契约套件二者皆容）。cancel(runId) 幂等。
- 契约要求「至少异步检查一次 signal」沿用（echo 验收遗留②）。
- healthCheck **只做只读探测、零付费调用**：二进制存在性（which）+ 登录态探测（codex 用 `codex login status`；gemini 查凭据文件存在性/`--version`；claude 未安装→`{ ok:false, detail:"claude CLI 未安装" }`）。detail 说人话，**绝不输出 token/密钥内容**。
- 三个适配器如需共享 spawn/流解析工具，允许新增 `plugins/agent-cli-utils`（包名 `@conductgun/agent-cli-utils`，private，不导出 AgentPlugin）——本任务书预批准，无需再仲裁；不要就三份重复代码。

### 3.7 CLI 增量（前端研发，`packages/cli`）

- `cg run --agent <id> "<text>"`：TaskSpec.preferredAgent = id，requiredCapabilities = []，artifacts 含 "diff"；默认（不带 --agent）仍走 echo，M0 行为不变。真实 agent 等待终态超时默认 600s（echo 保持 30s），`--timeout <sec>` 可覆盖。
- `cg run --no-wait`：只入队不消费，打印任务 id 后 exit 0（不起 WorkerHost）。
- `cg drain`：recover → 注册全部插件（echo + claude + codex + gemini）→ 起 WorkerHost（**启用 WorktreeManager**，repoRoot 取主仓库根）→ 等队列无 queued/running → 逐任务打印终态摘要 + worktree 路径 + diff 获取方式 → 空队列或超时退出。默认超时 600s，`--timeout` 可覆盖。
- `cg agents`：列出各插件 card 摘要 + healthCheck 结果（ok/不可用原因），低密度一行一个。
- 并行冒烟入口即：`cg run --agent codex --no-wait "<任务A>" && cg run --agent gemini --no-wait "<任务B>" && cg drain`。
- constraints 注入见 §3.4；assumptions 注明「M1: Router 未实现，用户原文直接作为 goal/instructions」。

1. `cg agents` → codex/gemini ok，claude 未安装。
2. `cg run --agent codex --no-wait "在 docs/smoke/ 下创建 codex-hello.md，内容写一句自我介绍，提交到当前分支"`
3. `cg run --agent gemini --no-wait "在 docs/smoke/ 下创建 gemini-hello.md，内容写一句自我介绍，提交到当前分支"`
4. `cg drain --timeout 900` → 两任务并行、均 done。
5. 证据记录：两个任务 id、分支 cg/codex/<id> 与 cg/gemini/<id>、worktree 路径、`git diff <baseCommit>` 内容；核查 origin 无新提交（禁 push 生效）、主工作区无改动。
6. 结果写入 AGENTS.md 同步日志（任务 id/分支/diff 位置）。
